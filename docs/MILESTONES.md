# 마일스톤

이 문서는 구현 이력이 아니라 **프로덕션 운영에 남은 작업**만 우선순위대로 관리한다.

## 닫지 않기로 한 갭

아래는 열지 않기로 한 것이다. 적어 두는 이유는 "아직 안 했다"와 "안 하기로 했다"가 문서에서
구별되지 않으면 다음 사람이 같은 판단을 다시 하기 때문이다.

| 갭 | 왜 마일스톤이 아닌가 |
|---|---|
| 전 엔티티의 일괄 정규화 | 대부분의 엔티티는 `items`의 키/JSONB 접근 패턴을 공유한다. 별도 질의나 저장 한도가 필요한 영역만 전용 테이블을 사용한다. Better Auth, 벡터 카탈로그와 SDK Session이 그 범위다. |
| Slack 이벤트의 급사 복구 | 재처리는 run 이 비멱등이라는 이미 내린 판단에 걸리고, schedule 의 "다음 발생"에 해당하는 자연스러운 재시도가 없다. 남는 것은 마감되지 않은 원장이 아니라 답을 못 받은 사용자이고, 복구 대상이 아니라 이미 사용자에게 보이는 실패다 (design/triggers.md). |
| 인스턴스 간 즉시 무효화 | 설정 override는 `SETTINGS_CACHE_TTL_MS`(기본 5초), email 기반 member tier는 별도 30초 캐시로 전파된다. 공유 무효화 신호는 없으며 각 경계의 실제 지연은 [보안 계약](SECURITY.md#인가-모델)을 따른다. |
| 기존 공개 이미지 URL 의 소급 차단 | 이미 배포된 오브젝트는 이미 공개다. 행을 다시 써도 도달성은 바뀌지 않으므로, 버킷을 비공개로 만드는 운영 조치가 유일한 해결이고 그건 코드 작업이 아니다 (SECURITY.md 의 *Data exposure and retention*). |

**결정이 필요한 갭은 또 다르다.** 위 표는 "안 하기로 했다"이고, 아래는 "완료 조건을 쓸 수
없어서 아직 마일스톤이 아니다"이다. 오른쪽 칸이 정해지는 순간 규약대로 위로 올라간다.

| 갭 | 마일스톤이 되기 전에 정해야 하는 것 |
|---|---|
| MCP 하위 호환 계층의 수명 | 프로토콜 era 협상과 RFC 7591 등록은 *의도적인* 하위 호환이다. 레지스트리 항목이 가리키는 것은 남의 배포이고, 이쪽이 올라갔다는 이유로 깨지면 그 소유자가 고칠 수 없다. 대가는 `design/mcp.md` 가 적어 두고 있다. 정할 것: **무엇을 관측해야 걷어낼 수 있는가**. 레지스트리의 모든 항목이 modern 이라는 사실을 어디서 읽는가(협상 결과는 지금 아무 곳에도 기록되지 않는다), 등록으로만 클라이언트를 받은 프로젝트가 남아 있는지를 어떻게 세는가. 두 신호가 생기기 전에는 완료 조건을 쓸 수 없고, 생기는 순간 조건은 자명하다. |
| Slack 참여 판단을 모델이 하는 쪽 | 지금 판단은 코드가 한다(`classifySlackEvent`). 키워드는 운영자가 미리 적어야 하고, "이건 나한테 온 질문인가"를 문장 단위로 읽지는 못한다. 정할 것: 그 판정을 무엇이 수행하고 비용을 누가 지는가. 채널 메시지마다 LLM 을 호출하면 프로젝트 일일 비용 가드가 런이 아닌 트래픽을 세게 되고, 오판은 채널에 그대로 남는다. 판정이 맞았는지 관측할 자리가 없으면 완료 조건을 쓸 수 없다. 아래 항목과 같은 공백이다. |
| 답변 품질에 대한 사용자 신호 | 어떤 답이 좋았는지 말할 수 있는 자리가 어느 표면에도 없다. Slack 에는 네이티브 피드백 블록이 있지만 답변은 blocks 가 아니라 markdown 으로 나가고 interactivity 엔드포인트도 없다(`/api/slack` 아래는 events 뿐). 정할 것: 신호를 어디에 적고 **무엇이 그것을 읽는지** 다. 읽는 쪽이 없으면 행만 쌓인다. |

**규약**

- 각 마일스톤은 **완료 조건**을 자동으로 확인할 수 있어야 한다. 확인 방법이 정해지지 않은
  작업은 마일스톤에 넣지 않는다.
- "한 곳에만 있다"는 완료 조건은 **테스트로 고정한다** (`tests/architecture.test.ts` 의
  single-owner 불변식). 서술로만 남은 단일 소유는 다음 진입점이 생길 때 조용히 깨진다.
- **선행**이 있는 마일스톤은 선행이 끝나기 전에 착수하지 않는다.
- **문서 순서가 우선순위이고, 기준은 *되돌릴 수 없는 정도* 다**. 심각도도 난이도도 아니다.
  기록하지 않은 날의 감사 기록은 소급 생성할 수 없고 이미 나간 URL 은 회수할 수 없는 반면,
  `running` 으로 멈춘 이력 행은 나중에도 마감할 수 있다. 순위를 바꾸려면 이 축에서 근거를 댄다.
- 완료된 마일스톤은 이 문서에서 제거한다. 이력은 git log 와 태그별 GitHub Release 가 source 다.
- **마일스톤을 가리키는 문서가 그 마일스톤의 일부다.** 범위를 좁히거나 지울 때 참조도 함께
  손본다. 확인은 `docs/` 에서 slug 를 grep 하는 것이고, 실제로 한 번 세 곳이 옛 약속을
  그대로 들고 있었다.
- 식별자는 **재사용하지 않는 slug** 를 쓴다. 완료된 것을 지우는 규약 때문에 번호는 반드시
  재사용되고, `M4` 는 실제로 세 가지 서로 다른 기능을 가리킨 이력이 있다.
- 동작 보존 작업은 기존 테스트를 수정해서 통과시키면 완료가 아니다.
- 최상위 런의 admission 정책은 `runBracket.ts`가 소유한다. Agent 입력·도구·승인 정책은
  SDK Runtime의 해당 메커니즘에 적용한다. 소유 경계는 [OWNERSHIP.md](OWNERSHIP.md),
  레이어와 wiring site 규칙은 [AGENTS.md](../AGENTS.md)를 따른다.
